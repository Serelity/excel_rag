# 字段边界：标注规范提供了哪些依据

核验日期：2026-10-08。状态：首轮定向调研完成；字段字典、模型和验收阈值尚待项目样例验证。

本报告围绕两个问题整理公开规范：同一投诉中的信息怎样区分和关联；对字段的不同要求怎样改变方法选择。已核验 5 份规范正文，来自 ACE、PropBank、TimeML 三套规范体系。ACE 的三份文档属于同一项目，不能算作三个独立研究结论。它们是任务定义和标注实践证据，均不构成中文投诉上的准确率证据。

本报告与[文献调研](01-literature-review.md)、[开源方案调研](02-open-source-review.md)互补。来源记录见 [guidelines.json](sources/guidelines.json)，实际访问与本次复核记录见 [boundary-search-log.jsonl](sources/boundary-search-log.jsonl)。页码按实际 PDF 页序标注；PropBank 同时注明正文印刷页码。

## 1. 首先区分四种边界

| 边界 | 要回答的问题 | 人工构造示例 | 规范依据与本项目仍需决定的内容 |
| --- | --- | --- | --- |
| 事项边界 | 哪些表述属于同一个待检索的问题 | “电梯坏了、报修、维修后仍坏”是否为一个事项 | ACE 区分事件提及、事件同指和子事件，但其新闻事件粒度不能替代投诉检索粒度。[G01] 本项目需要用相似案例检索目标裁决 |
| 文本片段边界 | 证据选哪几个字、是否连续、是否包含修饰语 | “小区西门外的工地”保留多大范围 | ACE 实体区分完整范围和中心词，允许嵌套；PropBank 用句法范围约束论元。[G02][G04] 本项目需要选择最短充分证据、完整短语或多片段证据的具体规则 |
| 语义角色边界 | 同一个实体或动作在这里起什么作用 | “住在甲小区，反映乙路工地施工” | 地点类别并不自动给出事发地、居住地等关系。ACE 区分地点实体与事件的 PLACE、ORIGIN、DESTINATION；PropBank 围绕具体谓词定义论元。[G01][G04] 投诉专用角色仍需定义 |
| 解释与推断边界 | 是原文复制、语义归纳、上下文解析还是外部补全 | “半夜吵得睡不着”能否归为“施工噪声” | 规范要求结合语义关系及模态判断；TimeML 显式区分时间表达、值、锚点和事件时间关系。[G01][G03][G05] 原文未提到施工时，归入施工类属于额外判断，需单独约束和评价 |

“边界清楚”不必意味着所有字段使用互不重叠的字符片段。G01 §6.1.1 p.50 的 **Shared Arguments** 明确要求：一个实体或值在同一句中对两个事件都合理适用时，应同时归属两个事件。G02 §5 p.26 也允许实体提及嵌套。

这里有严格的适用范围：G01 讲的是事件间共享论元，G02 讲的是实体提及嵌套。它们支持“可以设计重叠和共享机制”这一判断，**并未直接规定本项目的现象、影响、诉求是否应该复用同一片段**。例如“希望处理长期无人清运的垃圾”中的复用规则，还需要通过投诉样例和标注分歧决定。字段语义、片段重叠和跨事项共享应分别讨论。

## 2. 已核验规范来源

### G01：ACE English Annotation Guidelines for Events

- **机构与版本**：Linguistic Data Consortium；v5.4.3，2005-07-01。
- **来源**：[LDC 官方 PDF](https://www.ldc.upenn.edu/sites/www.ldc.upenn.edu/files/english-events-guidelines-v5.4.3.pdf)。完整 PDF 已取得；本次定向核验封面、§3 pp.18–21、§4 p.22、§6–6.1.1 pp.48–50。
- **原文支持**：§6.1 p.49 将事件发生地点 PLACE-ARG 与运动事件的 ORIGIN-ARG、DESTINATION-ARG 区分；后两者也是地点，却有专门角色。§6.1.1 p.50 的 Shared Arguments 允许语义成立的共享论元；Reasonable Reader Rule 要求在对应模态下有合理的语义归属。§3 将否定、时态、泛指性和模态分别讨论，命令、请求、愿望等并不等同于按已发生陈述。§4 以事件身份而非部分关系定义事件同指。
- **对项目的启发**：先识别某段话围绕哪个问题，再判断每个地点、主体和诉求与哪个问题有关；把“希望修好”与“已经修好”分别处理。共享地点或对象可以作为候选表示能力，需有归属证据。
- **限制**：ACE 的事件类型、句内作用域与新闻语料有明确边界。其“最近句法关系”规则不是“字符距离最近”；不能用现有字符近邻定位替代语义判断。事件定义也没有回答本项目应保留几个投诉事项。

### G02：ACE English Annotation Guidelines for Entities

- **机构与版本**：Linguistic Data Consortium；v6.6，2008-06-13。
- **来源**：[LDC 官方 PDF](https://www.ldc.upenn.edu/sites/www.ldc.upenn.edu/files/english-entities-guidelines-v6.6.pdf)。完整 PDF 已取得；定向核验封面、§3.3.3–3.3.4 pp.16–18、§5–5.1.2 pp.26–28。
- **原文支持**：§3.3.4 指出 GPE 提及的角色依赖上下文中的关系；例如同一地名可在不同语境中指向政府、人口或地点。§3.3.3 给出嵌套地域名称。§5 明确实体提及可以嵌套；§5.1 分别记录提及完整范围与中心词，且完整范围含修饰信息。
- **对项目的启发**：地址字符串或地点种类只是一个层次；它对投诉事项的角色需要另外判断。片段粒度应写进标注规则，否则“工地”和“甲路西侧工地”都可能被不同标注者认为正确。
- **限制**：GPE.ORG / GPE.LOC 是 ACE 对地缘政治实体提及的角色划分，不能直接改名成投诉的居住地 / 事发地。英文名词短语的范围、分词和嵌套规则也不能原样套用于中文地址。

### G03：ACE English Annotation Guidelines for Relations

- **机构与版本**：Linguistic Data Consortium；v6.2，2008-04-28。
- **来源**：[LDC 官方 PDF](https://www.ldc.upenn.edu/sites/www.ldc.upenn.edu/files/english-relations-guidelines-v6.2.pdf)。完整 PDF 已取得；定向核验封面、§2.1 pp.3–5、Modality and Tense pp.6–7、§3.1.1 pp.13–14。
- **原文支持**：Tagging for Meaning 和 Tag for Explicit Meaning 要求局部文本中有关系证据；外部知识或文档其他位置有事实，仍不自动让该句关系可标。Reasonable Reader Rule 用语义判断约束关系。Located 关系甚至限定其第一个参数为人，设施等另有关系类型。
- **对项目的启发**：抓到了“物业”“电梯”“小区”仍不足以判定谁被投诉、谁接到反馈、哪里出问题。每种关系应明确两端是什么、允许的上下文范围，以及何时证据不足。
- **限制**：这是句内关系规范；本项目若要跨句关联“后者”“该处”，需要另行定义并验证。该规范 p.6 不标否定关系，而 G01 会保留事件否定属性，说明不同任务规范不能未经裁决拼成一套标签。它也不支持“投诉里的全部地点都能作为强过滤条件”。

### G04：English PropBank Annotation Guidelines

- **作者与机构**：Claire Bonial、Julia Bonn、Kathryn Conger、Jena Hwang、Martha Palmer、Nicholas Reese；University of Colorado Boulder，CLEAR / Institute of Cognitive Science。
- **版本与来源**：封面日期 2015-07-14；[大学托管 PDF](https://verbs.colorado.edu/propbank/EPB-Annotation-Guidelines.pdf)。完整 PDF 已取得。定向核验 §1.1（PDF pp.4–5 / 正文 pp.3–4）、§1.4.2–1.4.4（PDF pp.13–14 / 正文 pp.12–13）、§1.4.10–1.4.14（PDF pp.17–20 / 正文 pp.16–19）、§1.5（PDF p.23 / 正文 p.22）。
- **原文支持**：论元标签相对于谓词及其词义定义；ARG0 / ARG1 等的具体含义并非对全部谓词完全固定。修饰角色区分位置、方向、目标、目的、原因、时间和否定。目的与原因的疑难情况有专门裁决规则；NEG 还说明不能见到 `not only` 就认定否定。
- **对项目的启发**：处理“向物业反映电梯坏了，希望维修”时，先区分“反映”“故障”“希望维修”等语义关系，再决定它们共同形成哪个投诉事项。“出现了某个关键词”只能提供候选，不能单独证明字段角色或否定作用域。
- **限制**：所读为英语、基于 Penn TreeBank 的版本；这里没有核验中文 PropBank 规则或任何中文 SRL 模型表现。其句法论元粒度与投诉检索事项粒度不同。主页指向的 current guidelines 本轮下载超时，本条只代表已读到的 2015 大学托管版本，不称其为最新版本。

### G05：TimeML Annotation Guidelines

- **作者与项目**：Roser Saurí、Jessica Littman、Bob Knippen、Robert Gaizauskas、Andrea Setzer、James Pustejovsky；文档引言说明来自 TERQAS 标注工作组与 TANGO workshop 的讨论和试标。
- **版本与来源**：v1.2.1，PDF 封面日期 2006-01-31；[TimeML 项目镜像 PDF](https://timeml.github.io/site/publications/timeMLdocs/annguide_1.2.1.pdf)，由[同站规范目录](https://timeml.github.io/site/publications/specs.html)链接。目录写 October 2005，本报告优先采用已核验 PDF 封面日期并保留差异。完整 PDF 已取得；定向核验 §2.2.2–2.2.3 pp.20–29、§2.4 pp.33–35、§2.4.3 与 §3.1 p.44、§3.2 pp.51–53。
- **原文支持**：TIMEX3 区分 DATE、TIME、DURATION、SET，文本范围、标准值、时间锚点和时间关系分别表达。MAKEINSTANCE 的否定和模态属于事件实例；SLINK 对愿望、承诺、报告等引入的事件关系作不同处理。p.33 还讨论重复事件采用基数还是多个实例，以及后文单独指向实例时的差别。
- **对项目的启发**：“每晚”“已经三天”“昨天修过今天又坏了”不能仅作同一种字符串处理；提取表达与解析时间分别需要验收。投诉人表达的事实、希望发生的动作和转述的说法，要保留其作用对象。
- **限制**：本条是旧版 TimeML 项目指南，不声称是当前 ISO 规范。规范允许部分隐式时间对象及上下文推导，本项目是否允许这种推导、用工单哪个时间作锚点，仍待决定。其细粒度事件实例也不能直接成为投诉事项。

## 3. 要求怎样决定方法和模型候选

下表是由规范任务定义导出的比较框架。方法类别是本报告的工程分析，不代表上述规范推荐了某个模型，也不代表已证明哪种方法最优。

| 如果字段要求是…… | 实际需要解决的任务 | 可以纳入比较的方法 | 必须单独检查的错误 |
| --- | --- | --- | --- |
| 只填原文明示、逐字可定位的值 | 片段识别与精确定位 | 规则、词典、序列 / span 抽取、带证据的 schema 引导抽取 | 漏提、多提、片段过长或过短、错配重复出现的位置 |
| 地点要知道“服务于哪个事项、什么角色” | 论元 / 关系抽取、指代与事项归属 | 事件论元或关系模型、联合抽取、带上下文的语言模型 | 地点本身对但事项错；居住地误作事发地；反馈接收方误作责任方 |
| 同一片段可能给多个事项提供信息 | 嵌套、重叠、共享关联 | 支持多标签 / span / 关系图的表示；可表达多重关联的生成输出 | 强制互斥而漏提；允许共享后把全部地点广播给全部事项 |
| 问题名称可以归一化 | 概念映射与信息保真 | 受控分类 / 词表映射、受约束生成 | 增加原文没有的事故、主体或因果；丢失否定、时间和怀疑条件 |
| 请求、否定、怀疑、转述与已解决要区分 | 模态、作用域、时序与话语关系 | 上下文分类、结构化属性 / 关系抽取、语言模型与规则校验 | “要求维修”变“已经维修”；过去未解决覆盖后来已解决；一个全局状态覆盖所有事项 |
| 地址或时间要变成可检索标准值 | 表面规范化、实体链接或时间解析 | 字典 / 地址库 / 时间解析器；必要时专门链接模型 | 原文值与推导值混存；无依据补全省市；使用错误时间锚点 |
| 结果须严格符合机器结构 | 类型、字段、跨字段约束 | JSON Schema、Pydantic、受约束解码、可审计重试 | 结构合法但语义错误；重试或长度限制使某些事项系统性遗漏 |

因此模型选型需要待四类信息明确后再做：输入中真实存在的困难类型；允许推断到哪一层；可提供的人工标注量；本地部署的延迟与资源要求。规范本身不能决定模型参数规模、量化方式或哪个开源模型在这 80 条投诉上更准确。

## 4. 与现有仓库的对照

以下只报告代码阅读事实，未执行模型推理，也未修改业务代码。

| 当前实现 | 对应边界 | 调研后的待验证事项 |
| --- | --- | --- |
| [schema.py](../../../semantic_extraction/schema.py) 用 `MAX_RETRIEVAL_ISSUES = 3` 限制事件列表；[prompt.py](../../../semantic_extraction/prompt.py) 按“需要不同知识答案”划分 | 事项单元、最大数量 | 该约束来自既有知识检索实验。历史案例匹配是否需要相同边界和数量，需要实际样例支持 |
| `behaviors`、`impacts`、`requests` 已分别定义 | 现象、后果、办理意图 | 明确最小充分片段、片段重叠与跨字段复用的规则；将歧义归因于规则还是模型 |
| `LocationMention.kind` 标记道路、小区、机构等类别 | 实体类别与语义角色 | 类别无法单独表达事发地 / 居住地 / 反馈目的地，也不能直接证明和某事项的关系 |
| [grounding.py](../../../semantic_extraction/grounding.py) 用连续子串查证据；重复出现时按与 trigger 的字符距离定位 | 证据存在与归属 | 可以发现原文不存在的引文；存在的片段仍可能被分配给错误角色或错误事项。ACE 的句法近邻规则也不能给此字符策略提供直接验证 |
| `polarity` 将 occurred、possible、negated、consultation 放在一组枚举 | 事实性、否定、言语目的 | 文献规范提示它们可能是不同分析维度；“咨询疑似问题”“否定某原因但肯定现象”等情况需样例裁决，暂不据此直接改 schema |
| 提示词优先当前最终诉求，已结束问题通常不再展开 | 历史背景与当前需求 | 相似案例检索是否仍需要曾发生的问题作检索依据，需要下游对比；不能直接沿用为业务真理 |

## 5. 下一轮设计前的边界核对材料

建议先准备少量人工构造对照句，再核对私有样本中的同类情况。以下不是新字段规范，也不是性能验收集。它们用于让标注者先说明判断理由，并暴露规则分歧。

| 构造对照 | 应观察的分歧 | 将影响什么选择 |
| --- | --- | --- |
| “住在甲小区，乙路工地施工” / “甲小区内部施工” | 地点角色、地址和事项的关联 | 仅实体抽取是否足够；是否需要角色关系 |
| “希望修好电梯” / “电梯已经修好” / “物业说已修好，但仍不能使用” | 请求、转述与实际陈述相冲突 | 是否需要多个命题及各自的来源和状态 |
| “垃圾无人清运，希望处理” / “希望处理长期无人清运的垃圾” | 同一含义换句式后，片段和字段是否一致 | span 粒度、嵌套、字段复用规则 |
| “甲楼漏水，乙楼停电，请先处理后者” | 跨句 / 分句指代与诉求归属 | 关系抽取、文档上下文能力 |
| “维修后再次漏水” / “漏水还导致停电” | 同一问题的过程与独立后果的拆分 | 检索事项粒度和漏提评估 |
| “怀疑多收费” / “并未多收费，只是询问计费规则” | 怀疑、否定、咨询的共存与作用域 | 属性集合是否充分；单个互斥标签是否丢信息 |
| “昨天开始” / “连续三天” / “每逢下雨” | 相对日期、时长、条件性频次 | 提取与归一化是否分步；是否有可靠时间锚点 |
| 同一地址在原文前后多次出现，分别谈不同问题 | 引文相同但所指位置不同 | 自动落字符位置是否需要语义复核 |

设计字段时至少写清：定义、纳入条件、排除条件、正例、反例、证据范围、重叠与共享、事项关联、缺失 / 冲突处理、允许的推断、对检索的用途。设计要求越明确，就越能判断是简单规则、监督抽取、生成模型，还是组合方案需要承担这个任务。

评价也应分别检查片段是否找对、角色是否找对、事项是否完整、是否无依据新增以及检索是否改善。JSON 合法率、证据子串命中率、人工语义一致率和检索相关性各自回答不同问题，不宜合并成一个“抽取成功率”。
