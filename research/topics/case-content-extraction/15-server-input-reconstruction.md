# 从服务器已有数据重建80条开发输入

日期：2026-10-08。用户确认之前实验的原始数据已在服务器上，后续通过Git同步代码，在`civic-rag-retrieval`环境中从已有数据准备输入，不再要求传输原始表或整份人工复核包。

## 实现与标准

[准备脚本](../../../deploy/prepare-case-contract-inputs.py)仅使用Python标准库和CPU，支持原始TSV的`case_content`、已有检索SQLite的`records.content`及候选JSONL的`content`。SQLite以只读连接和事务读取一致快照，包含已提交的WAL内容；不使用会忽略WAL的immutable模式。

[固定选择表](../../specs/case-contract-run-v1/development-selection.json)从本地已确认的80条开发输入生成，只公开B001–B080与原文UTF-8 SHA-256，并绑定规范清单、原人工复核清单及目标输入文件指纹。业务ID和原文均不进入Git。每条原文须精确匹配，最终文件也须与已复核准备包逐字节一致；不重新采样，不strip，不替换换行或做NFKC规范化。来源中同一原文重复出现时仍只产生对应的一个样例，并记录出现次数。

缺失任何一条或最终文件指纹不符都停止，未完成匹配前不创建输出目录。现有目录不覆盖，最终manifest最后写入。生成包可直接交给既有runner，无需改提示词、schema、抽取规则或H100服务入口。

服务器只重建模型所需的输入。原人工反馈和验收矩阵保留在本地，待模型输出回传后验收；脚本不生成或推断人工答案。清单保留原复核清单的指纹作为引用，并明确该原清单未复制到服务器。
