## 1. 当前研究问题

项目面向政务投诉受理辅助：**从投诉原文理解问题及关键条件，在历史库中找到可核对、可借鉴的案例，交由工作人员判断。**

最新问题是：`case_content` 中哪些信息值得单独处理，如何划分事项、绑定角色与原文依据，以及这些处理是否改善历史案例匹配或减少人工判断负担。

这与早期“找回历史知识引用”的评价目标不同，也不同于直接生成政策答案。当前没有充分证据支持固定字段、某个抽取模型或某种输入表示最优。

## 3. 已明确的约束与仍开放的决定

1. **模型和检索输入只使用 `case_content`。** `case_goal`、结构化地址、分类、处理结果、历史引用等不混入输入。来源 ID、时间等可以用于审计或抽样，外部相关性标签单独保存。现有输入约定见私有 `data/case-relevance-phase1-v1/data-familiarization-001.json`。
2. **原文保留并作为对照。** 简短问题表达和辅助字段需要通过比较证明价值，不能预设结构化必然更好。
3. **“5 个核心字段、3 个补充字段”仍是草案。** 不据此筛掉反例，也不把它写成已经接受的最终 schema。
4. **字段的类型与角色分开考虑。** 出现一个地点不代表它是事发地；实体被找到不代表它属于正确事项。
5. **逐字定位、概念归纳、关系判断和外部知识补全是不同任务。** JSON 合法、引文存在、语义正确和检索有用也需要分别检查。
6. **人工金标和业务裁决尚需真实人员完成。** 助手准备材料、检查格式、计算指标；已有自动输出或探索记录不替代人工标签。
7. **开发样例与正式评价隔离。** 已用于试验和规则修订的来源/关联组应纳入后续排除，不再包装成未见样本。

## 6. 已有抽取实现与新目标的差距

这些是需要通过样例判断的设计问题，尚未决定直接修改：

- v4 仍以“需要不同知识答案”为事项划分标准，最多 3 项；现在要判断是否适合历史案例匹配。人工金标准不应受三项上限限制。
- 当前/背景和最终诉求的区别主要体现于提示词与人工 gold；v4 输出本身没有 `case_status` 或独立 active/background 字段。
- 地点类别不能完整表达居住地、事发地等角色；重复引文按字符距离定位不能证明语义归属正确。
- 已解决的历史问题是否保留，要看查询目的；寻找同类历史案例时，不能一概按“已结束”判无用。
- 事实性、否定、咨询目的、时间与处理状态之间的边界仍待样例裁决。

具体对照见 [字段边界研究](topics/case-content-extraction/03-boundary-evidence.md)、[schema](../semantic_extraction/schema.py)、[prompt](../semantic_extraction/prompt.py)、[grounding](../semantic_extraction/grounding.py)。

## 8. 从这里继续的具体工作

最近的一步是形成**字段用途与边界样例表**，从现有 80 条候选中以开发用途审查会改变匹配的差异。建议记录：

| 内容 | 要回答的问题 |
| --- | --- |
| 原文证据及文本版本 | 信息在哪里，能否稳定回到原文 |
| 候选信息及所属事项 | 发生了什么，涉及什么对象，与其他事项如何区分 |
| 地点/主体角色 | 是事发地点、居住地点、被投诉方还是处理方 |
| 诉求、否定、状态与条件 | 什么差异会改变相似案例的适用性 |
| 用途 | 服务召回、排序、限制条件还是结果展示 |
| 允许变换与正反例 | 只定位片段、可规范化概括，还是需要关系判断；何时弃权 |
| 缺失、冲突与待裁决项 | 是正文没说、指代不明还是信息更正 |

然后在同一小规模比较中保留三类输入：原文、经过核对的简短问题表达、原文加辅助信息。分别记录字段依据/归属错误与前列案例可借鉴性，再决定模型或字段的投入顺序。只增强查询侧可以先复用现有索引；若做字段硬过滤，历史侧也必须有可比较且可靠的信息。

规则、专用片段/关系抽取、带指南和证据的语言模型、组合方法都是候选。当前没有理由仅因已有 Qwen3 工程就锁定模型，也无需先对 40 万历史文本全量重跑抽取。

正式第一阶段仍按 v1.1 协议执行：10 个独立场景、30 查询，6 场景校准、4 场景留出；问题与综合模式各 10 查询，纯地址模式不重排，共同池最多 500 对。该实验比较固定 hybrid 候选内的原排序、重排及有条件过滤，不自动扩展为抽取输入表示的正式实验。若扩展研究变量，需要相应设计独立的候选池和评价协议。

服务器侧尚需取得实际资源与结果证据：复用校园网 H100 的已有环境、BGE-M3/reranker 权重及 dense 索引，完成同进程联合预检；再依据真实人工审核和标签完成冻结、收集、校准、评价。0.9 是阈值选择的经验目标，不是已取得的相关率。
